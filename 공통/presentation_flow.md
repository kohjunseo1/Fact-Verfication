## 1. 주제와 해결하려는 문제

- **Fact Verification**: 주어진 문장이 사실인지, 외부 근거와 일치하는지 검증하는 작업
- **왜 필요한가**: LLM의 성능은 높아졌지만 할루시네이션은 여전히 발생 → 생성 결과를 검증하는 단계가 필수
- **왜 어려운가: multi-hop**: 정답을 판단하려면 여러 문서를 연결해야 하는 경우가 많고, 관련 정보가 여러 곳에 분산되어 있음
- 오른쪽 예시 그림:

```
Claim: The Assignation을 쓴 극작가는 1668년 계관시인이 되었다
  문서 1: The Assignation은 John Dryden이 쓴 희곡이다  ┐
  문서 2: John Dryden은 1668년 계관시인이 되었다      ┴→ 결론: 사실
→ 두 번째 문서(John Dryden)의 이름이 claim에 직접 등장하지 않음
```

## 2. 과제와 데이터

| 과제 | HoVer 데이터셋 | 우리 범위: 2-hop |
|---|---|---|
| 주어진 query와 관련된 사실을 2번의 hop 탐색으로 수집하고, 이를 바탕으로 claim을 검증하는 구조를 구축 (참고: FEVER, 학습: HoVer) | HotpotQA 기반 2~4-hop claim, 라벨 SUPPORTED / NOT_SUPPORTED, 코퍼스: 위키 첫 단락 약 **520만** 문서 | 공식 train 9,052 → `hpqa_id` 그룹 분할 train **8,166** / val **886**, test **1,126** |

- 주의: 클래스 불균형. train의 SUPPORTED 비율 **72%**, test **46%** → accuracy만으로는 성능을 판단할 수 없음

## 3. 팀 베이스라인 4종

```
claim → ① 1-hop 문서 → ② bridge(두 번째) 문서 탐색 → ③ 근거 문장 선택 → ④ 판정
```

| 팀원 | ② 접근 방식 | 핵심 특징 |
|---|---|---|
| 고준서 | 학습 RoBERTa + k-hop beam | 3·4-hop 확장 설계 |
| 이상민 | NER 개체 → 제목 검색 | 경량, 설명 가능 |
| 한기선 | 학습된 hop-2 검색기 | 2-hop 최고 수치 |
| 황혜림 | 위키 하이퍼링크 그래프 | 전체 hop 실측, 빠름 |

- 강조 숫자: **85%** — 실패의 85%는 두 번째 문서를 놓친 경우 → ②를 어떻게 푸느냐가 네 명의 차이

## 4. 평가 지표

| ① 검색 단계 | ② 판정 단계 | ③ 전체 평가 |
|---|---|---|
| 문서 Recall@k (정답 문서 2개 모두 포함) | Accuracy, Macro-F1, NOT_SUPPORTED recall (사실이 아닌 문장을 놓치지 않는 비율) | HoVer score: 라벨이 맞고 정답 문서마다 근거 문장을 찾았을 때만 정답 |

## 5. 대표 파이프라인 구조

핵심: **hop 1을 단서로 hop 2를 찾는다** (③④를 점선으로 묶어 강조)

| # | 단계 | 종류 | 내용 |
|---|---|---|---|
| ① | TF-IDF 검색 | 규칙 | 520만 문서 → top-100 |
| ② | RoBERTa 재정렬 | 학습 | 상위 2개 = hop 1 |
| ③ | 위키 제목 링크 | 규칙 | hop 1 본문 언급 → hop 2 후보 |
| ④ | RoBERTa hop-2 채점 | 학습 | P(a) × P(c\|a) → 문서 top-5 |
| ⑤ | RoBERTa 문장 선택 | 학습 | → 근거 5문장 |
| ⑥ | RoBERTa 검증기 | 학습 | SUPPORTED / NOT_SUPPORTED |

- 예시 줄: 후보 문서 100개 → The Assignation ("… by John Dryden") → 링크 후보 John Dryden (claim에 없는 이름) → hop 2 문서 확정 → 근거 "… Poet Laureate in 1668" → SUPPORTED
- 하단: 학습 모델 4개(②④⑤⑥), 검증기는 정답 근거가 아니라 실제로 검색된 근거로 학습 + 클래스 가중치

## 6. 핵심 아이디어와 결과

test 2-hop 성능 비교:

| 구분 | 문서 all-hit@5 | acc | macro-F1 | HoVer score |
|---|---|---|---|---|
| v1 단일 검색 | 57.7% | 0.737 | 0.736 | 0.362 |
| **multi-hop (v2.2)** | **84.2%** | **0.755** | **0.755** | **0.553** |

- 강조: 문서 all-hit@5 **84.2%** (v1 57.7%에서 상승)
- HoVer score 0.362 → 0.553, 공식 규칙(N=10) **0.591**
- 오류는 NOT_SUPPORTED → SUPPORTED 쪽에 집중

## 7. 논문과의 주요 차이

| 비교 항목 | 논문 | 우리 |
|---|---|---|
| 문서 간 연결 | 문서를 독립적으로 채점 | **hop 1을 조건으로 hop 2 채점** |
| 후보 범위 | TF-IDF top-20 안에서 재정렬 (천장 약 60%) | 위키 제목 언급으로 TF-IDF 밖까지 확장 |
| 모델·학습 | BERT-base, 전체 hop | RoBERTa-base, 2-hop 전용, 클래스 가중치 |

- 전체 파이프라인 정확도: 논문 BERT 73.7 → 우리 75.5
- 평가 범위 다름: 논문은 2~4-hop 전체, 우리는 2-hop

질문 대비(슬라이드에 없음): 2-hop 값이 있는 논문 Table 6과 비교하면 claim-only 정확도 57.5 vs 62.2, 정답 근거 정확도 79.8 vs 80.0 (arXiv 2011.03088v2).
