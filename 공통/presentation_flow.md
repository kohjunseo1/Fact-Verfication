## 1. 주제와 해결하려는 문제

- Fact Verification: 주어진 문장이 사실인지, **외부 근거와 일치하는지**를 검증하는 작업
- LLM은 수준이 매우 높아졌지만, 동작 원리상 사실과 다른 내용을 만드는 할루시네이션이 남아 있다. 그래서 생성 결과를 검증하는 단계로 fact verification이 여전히 중요하다.
- multi-hop: 여러 문서를 연결해야 판정 가능. 예) "The Assignation을 쓴 극작가는 1668년 계관시인이 되었다" → 두 번째 문서(John Dryden)의 이름이 claim에 없다

## 2. 과제와 데이터

- 과제: query에 관련된 hop을 탐색하고, 이를 바탕으로 응답하는 구조 구축 (참고 FEVER, 학습 HoVer)
- HoVer: HotpotQA 기반 2~4-hop claim, 라벨 SUPPORTED / NOT_SUPPORTED, 코퍼스는 위키 첫 단락 약 520만 문서
- 우리 범위: **2-hop** (공식 train 9,052 → `hpqa_id` 그룹 분할 train 8,166 / val 886, test 1,126)
- 주의점 한 줄: train은 SUPPORTED 72%, test는 46% → accuracy만으로 판단할 수 없음

## 3. 팀 베이스라인 4종

```
claim → ① 1-hop 문서 → ② bridge(두 번째) 문서 탐색 → ③ 근거 문장 선택 → ④ 판정
```

| | 고준서 | 이상민 | 한기선 | 황혜림 |
|---|---|---|---|---|
| ② bridge 탐색 | 학습 RoBERTa + k-hop beam | NER 개체 → 제목 검색 | 학습된 hop-2 검색기 | 위키 하이퍼링크 그래프 |
| 특징 | 3/4-hop 확장 설계 | 경량, 설명 가능 | 2-hop 최고 수치 | 전체 hop 실측, 빠름 |

- 메시지: 실패의 85%가 "두 번째 문서를 놓친 경우" → ②를 어떻게 푸느냐가 네 명의 차이

## 4. 평가 지표

| 단계 | 지표 |
|---|---|
| 검색 | 문서 Recall@k (정답 문서 2개 모두 포함) |
| 판정 | Accuracy, Macro-F1, NOT_SUPPORTED recall (사실이 아닌 문장을 놓치지 않는 비율) |
| 전체 | **HoVer score**: 라벨이 맞고 정답 문서마다 근거 문장을 찾았을 때만 정답 |

- 하한선(claim만 보고 판정) 0.622 / 상한선(정답 근거 입력) 0.800 사이에서 모든 결과를 해석

## 5. 대표 파이프라인 구조

```
claim
 ① TF-IDF top-100 (HoVer 제공)
 ② RoBERTa 문서 재정렬 → 상위 2개 = hop 1
 ③ hop 1 본문에 언급된 위키 제목 → hop 2 후보
 ④ RoBERTa hop-2 채점 P(a) × P(c|a) → 문서 top-5
 ⑤ RoBERTa 문장 선택 → 근거 5문장
 ⑥ RoBERTa 검증기 → SUPPORTED / NOT_SUPPORTED
```

- 학습 모델 4개(②④⑤⑥), 검증기는 정답 근거가 아니라 **실제로 검색된 근거**로 학습 + 클래스 가중치

## 6. 핵심 아이디어와 결과

- 논문 구조 그대로(v1)는 정답 문서의 42%를 첫 단계에서 놓침 → 찾은 문서를 단서로 다음 문서를 찾는 hop-2 검색기 추가

| (test 2-hop) | 문서 all-hit@5 | acc | macro-F1 | HoVer |
|---|---|---|---|---|
| 하한선 (claim만) | – | 0.622 | 0.620 | – |
| v1 단일 검색 | 57.7% | 0.737 | 0.736 | – |
| **multi-hop** | **84.2%** | **0.755** | **0.755** | **0.581** |
| 상한선 (정답 근거) | – | 0.800 | 0.800 | – |

- 상한의 94%까지 도달 → 병목이 검색에서 **판정기**로 이동 (오류는 NOT_SUPPORTED → SUPPORTED 쪽에 집중)

## 7. 논문 대비 결과

HoVer 논문(Jiang et al., 2020) 중 2-hop 값이 있는 표만 비교:

| 지표 (2-hop dev) | 논문 BERT | 우리 |
|---|---|---|
| claim-only 정확도 (Table 6) | 57.5 | 62.2 |
| 정답 근거 정확도 (Table 6) | 79.8 | 80.0 |
| 전체 파이프라인 정확도 | 73.7 (**2~4-hop 전체**) | 75.5 (2-hop) |

- 전체 파이프라인과 HoVer score는 논문이 hop별 값을 보고하지 않아, 슬라이드에 **"평가 범위 다름"** 을 표시
- 메시지: 같은 조건의 상한은 논문과 같고, 우리 파이프라인은 그 상한에 근접

## 8. 논문과의 주요 차이

| | 논문 | 우리 |
|---|---|---|
| 문서 간 연결 | 문서를 독립적으로 채점 | **hop 1을 조건으로 hop 2 채점** (가장 큰 차이) |
| 후보 범위 | TF-IDF top-20 안에서 재정렬 (천장 약 60%) | 위키 제목 언급으로 TF-IDF 밖까지 확장 |
| 모델·학습 | BERT-base, 전체 hop | RoBERTa-base, 2-hop 전용, 클래스 가중치 |

## 9. 이후 시도

- **팀원 파이프라인에서 가져올 것**
  - 황혜림: 하이퍼링크 그래프를 hop-2 후보에 추가 (2-hop 정답 쌍의 87%가 직접 링크로 연결됨)
  - 고준서: k-hop beam search로 3/4-hop 확장
  - 이상민: 개체 기반 경로로 판정 근거 설명, 경량 모델 서빙
- **아키텍처와 기술**
  - 판정기 교체: NLI로 사전학습된 DeBERTa-v3-large (현재 병목)
  - Dense multi-hop 검색 (MDR, Baleen)
  - LLM claim 분해(ProgramFC), 확신도 낮은 claim만 LLM 또는 사람이 재검토
